| K-04 | Medium | PDFs with real text are extracted on device (pure Kotlin). Photos and scanned PDFs can be read with a vision AI provider (OpenAI, Gemini, Claude) on explicit request; this sends the images to that provider and needs cloud AI allowed. Scanned PDFs need page rendering, which exists on Android (PdfRenderer) but not in the desktop harness. Since 2026-10-30 Arabic and Urdu photos and scanned PDFs can also be read on the device with Tesseract (bundled tessdata_fast models, nothing sent anywhere); printed Arabic in Naskh is read well, Urdu in Nastaliq poorly (a test line came back as "تةہاراووست ہوں۔" for "میں تمہارا دوست ہوں۔" and a second line was missed; the larger tessdata_best Urdu model gave the same result and was not adopted). The Arabic model was not run on the device (Arabic cannot be a learning language with the Arabic interface); the Urdu model was. No on-device OCR for the other six languages (their models would add about 16 MB); Tesseract adds about 11 MB to the release APK; no audio/video transcription; encrypted PDFs and LZW content unsupported. Arabic/Hebrew lines are ordered by glyph position; multi-column layouts can come out in the wrong order | Paste text or import .txt/.srt/.vtt for unsupported files |
